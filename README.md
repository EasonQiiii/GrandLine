# GrandLine

macOS 局域网直传工具。当 AirDrop 与无线网络被禁用时，用有线/普通局域网完成与 AirDrop 等价的文件投送体验。

不依赖 AWDL、不依赖 Wi-Fi、不依赖 mDNS 守护进程 —— 只要两台机器在同一网段且 TCP 可达。

界面为英文；传输协议与发现机制均为自定义实现，二进制体积约 1 MB，无任何第三方依赖。

---

## 一、功能对照

| AirDrop 能力 | GrandLine 实现 |
| --- | --- |
| 自动发现附近设备 | UDP 广播心跳（每 1.5 秒），6 秒无心跳即离线 |
| 拖拽文件到设备上投送 | 支持拖拽到设备卡片，或点击卡片选择文件 |
| 文本 / 剪贴板快传 | 悬停设备卡片点粘贴按钮，或 `⌘K` 面板发送；接收端确认后直接进入其剪贴板，货舱同时留档 |
| Dock / Finder 发送 | 把文件或文件夹拖到 Dock 图标，或 Finder「打开方式 → GrandLine」；单设备直发，多设备弹窗选择 |
| 后台到达提醒 | App 不在前台时传输完成发系统通知，点击唤起主窗口 |
| 「仅联系人」式限制 | 可选 4 位 PIN，发送方必须输入正确 PIN |
| 信任设备免确认 | 接收弹窗勾选「Trust」后，该设备后续投送自动接收（同时免 PIN），设置里可随时移除 |
| 企业网固定直连 | 设置里按 IP 添加「Direct Beacon」，广播被抑制的网络也能投送 |
| 图片 / 文件 / 文件夹 | 文件直传；文件夹自动用 `ditto` 打包为 zip |
| 接收方确认弹窗 | 系统级浮动面板，展示发送者、文件清单、总大小 |
| 传输进度 / 速度 / 剩余时间 | 实时进度条 + MB/s + 剩余时间估算 |
| 传输中途取消 | 双方均可随时中断 |
| 接收后直接可用 | 自动落到 `~/Downloads/GrandLine/<发送者名>/` |
| 本机昵称 / 头像 | 设置 → IDENTITY：默认取电脑名，可改名、换头像，立即生效 |
| 暂停可见性 | 关闭顶部开关即「冻结」：界面去色、停止广播与接收，顶栏显示 Frozen |
| 多网段选择 | 列出本机全部网卡（以太网 / Wi-Fi / VPN），可逐个开关收发 |
| 上百台设备里定位目标 | `⌘F` 检索（名字 / 机型 / IP 片段，空格分词为「且」）；默认按成功传输次数排序，传得越多越靠前 |

## 二、架构

```
┌──────────────┐   UDP 47820 (广播心跳)   ┌──────────────┐
│   GrandLine A  │ ◄──────────────────────► │   GrandLine B  │
│              │                          │              │
│  Discovery   │   TCP 47821..47880       │  Discovery   │
│  TransferServer ◄────────────────────►  │  TransferClient
└──────────────┘   offer→accept→item→done └──────────────┘
```

**发现层**（`DiscoveryService`）
- 每 1.5 秒向各网卡的定向广播地址发送 JSON 心跳，含设备 ID、名称、机型和 TCP 端口。
- 对端 IP 直接取自数据包源地址 —— 多网卡（以太网 + VPN + 虚拟网卡）场景不会选错地址。
- **按网卡隔离**：每条启用的网段使用独立发送 socket，并通过 `IP_BOUND_IF` 钉死在对应接口，避免多网卡时全部走默认路由；接收侧按来源 IP 所属网段过滤，关闭某网段后其设备立即消失。
- 使用 `SO_REUSEPORT`，同机多实例可共存。
- **列表回写节流**：收到的每个心跳只打标记，200 ms 合并发布一次。上百台设备时心跳可达每秒上百个，逐包回写会让主线程反复重建列表。

**传输层**（`TransferServer` / `TransferClient`）
- 自定义帧协议，长度前缀 + JSON 头 + 原始字节流。
- 文件内容按 1 MB 分块流式发送，4 块滑动窗口，内存占用恒定（40 GB 的文件也不会爆内存）。
- 接收端边收边写盘，不做整体缓冲。

**协议时序**

```
Client                          Server
  │──── offer {items[], pin?} ────►│  校验 PIN → 弹窗询问用户
  │◄──── accept / reject ──────────│
  │──── item#0 {header+len} ──────►│  打开文件句柄
  │──── payload (1MB chunks) ─────►│  边收边写
  │──── item#1 ... ───────────────►│
  │──── done ─────────────────────►│
  │◄──── done ─────────────────────│
```

## 三、构建与运行

```bash
cd /Users/eewiki-2/WorkBuddy/AirDrop-like
./build.sh          # 产出 GrandLine.app（无需 Xcode 工程）
open GrandLine.app
```

要求：macOS 14+，Xcode Command Line Tools。

首次运行时系统可能询问「允许 GrandLine 查找本地网络设备」，必须允许，否则发现不到设备。

## 四、使用

1. 两台 Mac 连同一台交换机 / 同一路由器（有线优先）。
2. 都打开 GrandLine，顶部开关保持开启。
3. 把文件拖到对方设备卡片上，或点击卡片选择文件。
4. 对方收到弹窗，点「接收」即开始传输。
5. 文件落在 `~/Downloads/GrandLine/<发送者名>/`。

**设备太多时**：`⌘F`（或点 Find）打开检索条，按名字、机型或 IP 片段过滤，空格可分隔多个关键词（之间为「且」），回车直接向第一个结果发起投送，`Esc` 清空后关闭。默认顺序按与每台设备成功传输的次数排——传得越多越靠前，次数相同再按名称字典序（重名按 IP 数值序兜底，保证同名机器位置稳定不跳）。次数按设备 ID 持久保存，设备离线不清零、改名不影响；计数只在后台用于排序，界面上不显示。

**开启 PIN**：右上角设置图标 → 打开「要求 PIN 码」→ 生成 4 位 PIN。开启后对方发送时必须输入。信任设备（见下）不受 PIN 限制。

**信任设备**：收到投送时勾选弹窗里的「Trust」，该设备此后自动接收（同时免 PIN），航海日志与底部胶囊照常提示。设置 → TRUSTED SHIPS 可随时移除。

**固定 IP 直连**：设置 → DIRECT BEACONS → 输入对端 IP（端口默认 47821）→ Add。手动添加的对端固定显示在设备区，适用于广播被交换机抑制的企业网络。

**再发一次**：航海日志（⌘T）里已完成的航程行悬停可见 ↻ 按钮，点击即向原目标重发（按设备 ID 匹配，回退按名字；源文件已删除的条目会被过滤）。

**昵称与头像**：设置 → IDENTITY。昵称默认跟随电脑名（留空或与电脑名一致即自动跟随），修改后立即更新广播；头像从本地图片选择，居中裁切压缩为 256×256 存于 `~/Library/Application Support/GrandLine/avatar.png`，显示在顶栏与扫描区中心。

**只收不发 / 只发不收**：关闭顶部总开关即停止广播与接收。此时内容区整体去色表示「冻结」，并出现 Frozen 提示条与 Resume 按钮。

**文本快传**：复制任意文本后，悬停在设备卡片上点击右下角的粘贴按钮即可发送；或按 `⌘K` 打开发送面板（多设备时用 `↑`/`↓` 选择目标）。对方会弹出与文件相同的确认浮窗（内含文本预览），接受后文本直接写入其剪贴板（⌘V 即可粘贴），同时在 `~/Downloads/GrandLine/<发送者名>/Clipboard Text.txt` 留档。剪贴板为非文本内容（图片、文件引用）时不显示粘贴按钮。

**顶栏绿点**：传输图标右上角的绿点表示「有已完成但未查看的传输」，打开传输面板后自动清除；传输进行中则显示蓝色数量角标。

## 五、快捷键

| 快捷键 | 功能 |
| --- | --- |
| `⌘R` | 扫描附近设备 |
| `⌘F` | 检索设备（名字 / 机型 / IP） |
| `⌘K` | 发送剪贴板文本 |
| `⌘D` | 收放锚（开启 / 暂停接收与广播） |
| `⌘T` | 打开 / 聚焦航海日志（传输记录） |
| `⌘O` | 打开货舱（接收目录） |
| `⌘,` | 设置 |
| `⌘?` | 内置使用说明（顶栏 ？ 按钮同效） |
| `Esc` | 关闭日志抽屉 / 设置面板 / 悬赏令弹窗 |
| `⌘W` / `⌘M` | 关闭窗口 / 最小化 |
| 输入框内 `⌘C/⌘V/⌘A` | 编辑（昵称、PIN） |

悬赏令弹窗内：`Esc` = 拒收，`Return` = 接收。

## 六、已知限制

1. **明文传输**。局域网内若存在抓包者，文件内容可被截获。当前版本定位是受控内网的便捷传输，不适用于对保密性有强制要求的场景。后续可加 TLS（`NWProtocolTLS` + 自签名证书指纹校验）。
2. **PIN 明文随 offer 发送**，只防误投，不抗主动攻击。
3. **跨网段不可用**。广播不出路由器，这是设计取舍（需求即「仅本地局域网」）。
4. **未做代码签名公证**。`build.sh` 做的是 ad-hoc 签名，仅本机可运行；拷给别人需对方在「系统设置 → 隐私与安全性」中放行。
5. 企业网络中若交换机开启了广播风暴抑制 / 端口隔离，发现会失败 —— 已提供固定 IP 直连（设置 → DIRECT BEACONS）作为兜底。
6. **头像仅在本机展示**。UDP 心跳载荷只携带昵称与机型（约 200 字节），未包含图片，因此对端设备卡片显示的是昵称 + 按设备 ID 生成的配色图案。若要让对端看到头像，需扩展协议（独立小图请求或把压缩头像塞进心跳并处理分片），当前版本未做。

## 七、测试钩子（环境变量）

仅用于自动化验证，正常使用无需设置：

| 变量 | 作用 |
| --- | --- |
| `GRANDLINE_NAME` | 覆盖广播的设备名 |
| `GRANDLINE_DEVICE_ID` | 覆盖设备 ID，用于同机多实例 |
| `GRANDLINE_AUTO_ACCEPT=1` | 自动接受入站请求 |
| `GRANDLINE_AUTO_SEND=/path/a,/path/b` | 发现首个设备后自动投送 |
| `GRANDLINE_AUTO_SEND_TEXT=1` | 发现首个设备后自动投送当前剪贴板文本 |
| `GRANDLINE_UI=settings` | 启动时直接展开设置面板（传输面板不会自动展开） |
| `GRANDLINE_UI=transfers\|settings` | 启动时直接展开对应面板（界面预览用） |

端到端验证脚本（同机双实例）：

```bash
./GrandLine.app/Contents/MacOS/GrandLine &                                   # 接收端
GRANDLINE_NAME=B GRANDLINE_DEVICE_ID=id-b \
  GRANDLINE_AUTO_SEND="/tmp/a.bin,/tmp/folder" \
  ./GrandLine.app/Contents/MacOS/GrandLine &                                 # 发送端
```

## 九、传输性能参考

本机环回（同一台 Mac 双实例）实测：40 MB 文件约 1 秒内完成，校验 MD5 一致。真实千兆有线网络预期 80–110 MB/s，瓶颈在磁盘读写而非协议开销。
